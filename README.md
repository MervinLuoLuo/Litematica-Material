# Litematica 建造材料清单

一个零依赖、纯静态的网页工具：读取 Minecraft Litematica 模组导出的材料 CSV，在前端展示每种材料还需准备的数量（`Missing − Available`），换算成组（1 组 = 64 个，按 0.5 组步长取整）与「盒 + 余组」（1 盒 = 27 组，盒数向下取整），并为每种材料显示预览图、支持勾选收集进度。

## 功能

- 上传 / 拖拽 / 粘贴 CSV 文件，全部在浏览器本地解析，数据不会离开你的设备
- 展示每种材料**还需准备**的数量（`Missing − Available`），并换算为组数（0.5 步取整）与「盒 + 余组」（盒数下取整），例如 30 组 → 「1 盒 3 组」
- `Available` 列参与计算（已有数量），第 4 列之后的多余字段（例如 `0.68 SB` 这类附加标注）会被忽略
- 汇总统计：材料种类、需准备总数、约需组数、盒 + 余组、完成度
- 按名称搜索，按需准备 / 总量 / 名称排序；可筛选「展示全部 / 仅展示未收集完成 / 仅展示已收集完成」
- 每个材料可勾选「收集完成」：点击卡片或勾选框，卡片背景变浅绿，进度自动保存在浏览器本地（localStorage）；**需准备数量为 0 的材料会自动标记为已完成**（无法取消）
- 材料预览图：把图片文件放进 `images/` 文件夹即可自动显示（见下文）

## 快速开始

直接双击用浏览器打开 `index.html` 即可使用（推荐部署到服务器，预览图自动加载更稳定）。

本地预览时可用自带服务器：

```bash
node server.js
# 然后访问 http://localhost:8080
```

没有 Node 也可以：

```bash
python -m http.server 8080
# 然后访问 http://localhost:8080
```

用 `sample.csv` 上传测试即可看到效果。

## 部署到服务器

因为是纯静态页面，任何静态托管方式都行：

1. **自带服务器**：把整个文件夹上传到服务器，运行 `node server.js`（端口可用环境变量 `PORT` 修改）。
2. **Nginx 示例**：

   ```nginx
   server {
       listen 80;
       server_name your-domain.com;
       root /var/www/litematica;   # 指向本文件夹
       index index.html;
   }
   ```

3. **GitHub Pages / 任意静态托管**：把文件夹内容直接推送或上传即可，相对路径保证在子目录下也能正常工作。

## CSV 格式说明

读取前四列：`Item` / `Total` / `Missing` / `Available`。**还需准备的数量 = `Missing − Available`**（不小于 0），界面展示和换算都基于它：

```csv
"Item","Total","Missing","Available"
"石头按钮",1320,1283,0
"平滑石头台阶",516,442,31
```

- `Item`：材料名称（会用于匹配预览图文件名）
- `Total`：项目需要的总量
- `Missing`：还缺的数量
- `Available`：你目前已有的数量，参与计算但不在界面单独展示
- 第 4 列之后的多余字段（例如 `0.68 SB` 这类附加标注）一律忽略

表头行（`Total` 不是数字）会被自动跳过；`Available` 字段形如 `0, 0.68 SB` 时自动取逗号前的整数；文件带 BOM、行尾为 CRLF 均兼容。

## 换算规则

- 1 组 = 64 个
- 1 个潜影盒 = 27 组 = 1728 个
- 需准备 = `max(0, Missing − Available)`
- 组数按 **0.5 组步长**取整：整组 = `floor(需准备 ÷ 64)`，余数 `r = 需准备 mod 64`：
  - `r = 0` → 不加；`0 < r ≤ 32` → +0.5 组；`r > 32` → +1 组
  - 例：64 → 1 组；96 → 1.5 组；128 → 2 组；385 → 6.5 组；112 → 2 组
- 盒数与余组：盒数 = `floor(组数 ÷ 27)`，向下取整；余组 = `组数 mod 27`（可能带 0.5）
  - 例：30 组 → 「1 盒 3 组」；30.5 组 → 「1 盒 3.5 组」；9 组 → 「0 盒 9 组」
- 完成度 = `(总量 − 需准备) ÷ 总量`；汇总栏按同样的规则，用需准备总数统一换算

## 添加材料预览图（重点）

图片全部由你自己提供，网站只负责加载和展示。有三种方式，按优先级依次尝试：

### 方式一：默认命名约定（最简单）

把图片放进 `images/` 文件夹，**文件名与 CSV 中的材料名完全一致**即可，无需任何配置：

```
images/石头按钮.png
images/凋灵玫瑰.png
images/泥土.png
```

支持 `.png` / `.webp` / `.jpg` / `.jpeg` 四种后缀，页面会按顺序自动尝试。

> 提示：可以从 Minecraft Wiki、游戏 jar 包（`assets/minecraft/textures/item/` 或 JEI 的物品图标）导出 PNG 图标。

### 方式二：previews.json 自定义映射（推荐用于复杂文件名）

编辑站点根目录的 `previews.json`，把材料名映射到图片文件：

```json
{
  "石头按钮": "stone_button.png",
  "凋灵玫瑰": "wither_rose.png"
}
```

- 值可以是 `images/` 目录下的文件名（如上），也可以是完整外链：

  ```json
  {
    "樱花木活板门": "https://example.com/cherry_trapdoor.png"
  }
  ```

- 没有在映射中出现的材料，回退到方式一的默认命名约定。

### 方式三：什么都不放

没有对应图片的材料会显示一个「首字占位块」（暖色浅底 + 材料名首字），页面依然完整可用。

### 常见问题

- **图片不显示**：先确认文件名与 CSV 里的材料名**逐字一致**（含空格与标点），再确认图片确实在 `images/` 目录下。浏览器开发者工具（F12 → Network）里能看到实际请求的图片 URL。
- **材料名含特殊字符**（如 `/`、`\`、`?`）：默认约定可能失效，请改用方式二的 `previews.json` 映射。
- **改了图片不刷新**：浏览器会缓存图片，强制刷新（Ctrl+F5）即可。

## 常见问题

- **为什么我的 CSV 解析出来是空的？** 确认文件确实包含 `Item,Total,Missing,Available` 四列（顺序要一致），且 `Total` / `Missing` 是数字。
- **Available 列会显示吗？** 不会单独展示，但它参与计算：需准备数量 = `Missing − Available`。
