# Litematica 建造材料清单

一个基于 Node.js（零依赖）的网页工具：读取 Minecraft Litematica 模组导出的材料 CSV，展示每种材料还需准备的数量（`Missing − Available`），换算成组（1 组 = 64 个，按 0.5 组步长取整）与「盒 + 余组」（1 盒 = 27 组，盒数向下取整）。支持多套**档案**（材料清单）与收集进度保存在服务器上，可跨设备、跨浏览器同步。

## 功能

- **档案系统**：右上角可新建 / 选择 / 编辑 / 删除档案，每套档案包含档案名、CSV 内容、档案描述，保存在服务器 `data/archives.json`，跨设备 / 浏览器同步
- 上传 / 拖拽 / 粘贴 CSV（支持文件或文本粘贴），保存为档案后即可展示
- 展示每种材料**还需准备**的数量（`Missing − Available`），并换算为组数（0.5 步取整）与「盒 + 余组」（盒数下取整），例如 30 组 → 「1 盒 3 组」
- `Available` 列参与计算（已有数量），第 4 列之后的多余字段（例如 `0.68 SB` 这类附加标注）会被忽略
- 汇总统计：材料种类、需准备总数、约需组数、盒 + 余组、完成度
- 按名称搜索，按需准备 / 总量 / 名称排序；可筛选「展示全部 / 仅展示未收集完成 / 仅展示已收集完成」
- 每个材料可勾选「收集完成」：卡片背景变浅绿，**完成后带过渡动画移到列表最下方**，进度同步保存在服务器；**需准备数量为 0 的材料会自动标记为已完成**（无法取消）
- 材料预览图：把图片文件放进 `images/` 文件夹即可自动显示（见下文）

## 文件结构

```
Litematica Material/

```

## 快速开始

```bash
node server.js
# 然后访问 http://localhost:8080
```

启动后，点右上角「新建档案」，填写档案名，粘贴或上传 `sample.csv` 的内容即可查看效果。

页面右上角会显示当前模式：**服务器模式**（档案存服务器、可跨设备同步）或**本地模式**（连不上后端时自动降级，档案存当前浏览器 localStorage）。

## 启动并让外部 IP 访问

服务器默认监听 `0.0.0.0`（所有网卡），启动时会在控制台打印本机可访问地址：

```bash
node server.js
# 输出示例：
#   本机访问:  http://localhost:8080
#   局域网访问: http://192.168.x.x:8080
#   公网访问请使用云服务器控制台显示的公网 IP，并确认安全组/防火墙已放行该端口
```

外部设备访问 `http://服务器公网IP:8080` 前，需要放行端口：

- **云服务器**：在云控制台（阿里云 / 腾讯云 / AWS 等）的「安全组」中添加入方向规则，放行 TCP 8080（或你设置的端口）。
- **系统防火墙**（Linux）：

  ```bash
  # Ubuntu / Debian（ufw）
  sudo ufw allow 8080/tcp

  # CentOS / Rocky（firewalld）
  sudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload
  ```

- **常用端口**：想直接用 `http://公网IP` 访问（不带端口），可 `PORT=80 node server.js`（需要 root 权限）；或参考下文用 Nginx 反代。
- **仅本机访问**：`HOST=127.0.0.1 node server.js` 可限制只有本机能访问。

> ⚠️ 安全提示：本工具**没有登录鉴权**，知道地址的人都能查看和修改档案。暴露到公网时建议：加 Nginx 基本认证、限制来源 IP，或定期备份 `data/archives.json`。

## 部署方式（三种）

### 方式一：完整同步版（推荐）

用 `node server.js` 部署，档案与勾选进度存在服务器，跨设备 / 浏览器同步：

1. 把整个文件夹上传到服务器，运行 `node server.js`（端口可用环境变量 `PORT` 修改），保证 `data/` 目录可写。
2. 若用 Nginx 反向代理：

   ```nginx
   server {
       listen 80;
       server_name your-domain.com;
       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
       }
   }
   ```

3. 若使用 Docker / systemd 等部署，保持 `data/` 目录持久化即可，档案不会因重启丢失。

### 方式二：GitHub Pages 静态部署（本地模式）

GitHub Pages 无法运行 Node.js，但前端已内置**本地降级模式**：请求档案接口失败时自动改用浏览器 localStorage 存储，界面功能完全一致，只是数据不跨设备同步。

部署步骤：把 `index.html`、`styles.css`、`app.js`、`previews.json`、`images/` 等静态文件推送到 GitHub 仓库，在仓库 Settings → Pages 开启即可。

### 方式三：静态页 + 免费云后端（保留同步）

前端放 GitHub Pages，后端 `server.js` 部署到 Render / Railway / Fly.io 等免费服务，通过 API 地址配置对接（`server.js` 已内置 CORS 支持）：

- 临时方式：访问地址后加参数，例如 `https://你的用户名.github.io/仓库名/?api=https://your-app.onrender.com`
- 固定方式：在加载 `app.js` 之前设置全局变量，例如在 `index.html` 的 `<script src="app.js">` 前加一行：

  ```html
  <script>window.API_BASE = 'https://your-app.onrender.com';</script>
  ```

> 提示：配置了 `api` 参数或 `window.API_BASE` 后，页面会请求该后端；后端不可达时仍会自动降级为本地模式。

## 档案（多套材料清单）

右上角工具条管理档案，每套档案包含：

1. **档案名**：必填，用于在列表中区分
2. **CSV 内容**：必填，可通过「上传 CSV 文件」或直接粘贴文本记录
3. **档案描述**：可选，记录用途说明

- 新建：点「新建档案」→ 填写并保存；也可直接把 CSV 拖入上传区，会自动打开新建窗口并填入内容
- 切换：右上角下拉框选择档案，内容与收集进度立即切换
- 编辑：当前档案的「编辑档案」按钮，可修改名称 / 描述 / CSV
- 删除：当前档案的「删除档案」按钮（需确认，不可恢复）
- 同步：档案与勾选进度都存在服务器 `data/archives.json`，任何设备打开同一地址都能看到相同内容；地址带 `?a=档案id` 可直接定位到指定档案

## CSV 格式说明

读取前四列：`Item` / `Total` / `Missing` / `Available`。**还需准备的数量 = `Missing − Available`**（不小于 0），界面展示和换算都基于它：

```csv
"Item","Total","Missing","Available"
"石头按钮",1320,1283,0
"平滑石头台阶",516,442,31
```

- `Item`：材料名称（会用于匹配预览图文件名）
- `Total`：项目需要的总量
- `Missing`：还缺的数量
- `Available`：你目前已有的数量，参与计算但不在界面单独展示
- 第 4 列之后的多余字段（例如 `0.68 SB` 这类附加标注）一律忽略

表头行（`Total` 不是数字）会被自动跳过；`Available` 字段形如 `0, 0.68 SB` 时自动取逗号前的整数；文件带 BOM、行尾为 CRLF 均兼容。

## 换算规则

- 1 组 = 64 个
- 1 个潜影盒 = 27 组 = 1728 个
- 需准备 = `max(0, Missing − Available)`
- 组数按 **0.5 组步长**取整：整组 = `floor(需准备 ÷ 64)`，余数 `r = 需准备 mod 64`：
  - `r = 0` → 不加；`0 < r ≤ 32` → +0.5 组；`r > 32` → +1 组
  - 例：64 → 1 组；96 → 1.5 组；128 → 2 组；385 → 6.5 组；112 → 2 组
- 盒数与余组：盒数 = `floor(组数 ÷ 27)`，向下取整；余组 = `组数 mod 27`（可能带 0.5）
  - 例：30 组 → 「1 盒 3 组」；30.5 组 → 「1 盒 3.5 组」；9 组 → 「0 盒 9 组」
- 完成度 = `(总量 − 需准备) ÷ 总量`；汇总栏按同样的规则，用需准备总数统一换算

## 添加材料预览图（重点）

图片全部由你自己提供，网站只负责加载和展示。有三种方式，按优先级依次尝试：

### 方式一：默认命名约定（最简单）

把图片放进 `images/` 文件夹，**文件名与 CSV 中的材料名完全一致**即可，无需任何配置：

```
images/石头按钮.png
images/凋灵玫瑰.png
images/泥土.png
```

支持 `.png` / `.webp` / `.jpg` / `.jpeg` 四种后缀，页面会按顺序自动尝试。

> 提示：可以从 Minecraft Wiki、游戏 jar 包（`assets/minecraft/textures/item/` 或 JEI 的物品图标）导出 PNG 图标。

### 方式二：previews.json 自定义映射（推荐用于复杂文件名）

编辑站点根目录的 `previews.json`，把材料名映射到图片文件：

```json
{
  "石头按钮": "stone_button.png",
  "凋灵玫瑰": "wither_rose.png"
}
```

- 值可以是 `images/` 目录下的文件名（如上），也可以是完整外链：

  ```json
  {
    "樱花木活板门": "https://example.com/cherry_trapdoor.png"
  }
  ```

- 没有在映射中出现的材料，回退到方式一的默认命名约定。

### 方式三：什么都不放

没有对应图片的材料会显示一个「首字占位块」（暖色浅底 + 材料名首字），页面依然完整可用。

### 常见问题

- **图片不显示**：先确认文件名与 CSV 里的材料名**逐字一致**（含空格与标点），再确认图片确实在 `images/` 目录下。浏览器开发者工具（F12 → Network）里能看到实际请求的图片 URL。
- **材料名含特殊字符**（如 `/`、`\`、`?`）：默认约定可能失效，请改用方式二的 `previews.json` 映射。
- **改了图片不刷新**：浏览器会缓存图片，强制刷新（Ctrl+F5）即可。

## 常见问题

- **为什么我的 CSV 解析出来是空的？** 确认文件确实包含 `Item,Total,Missing,Available` 四列（顺序要一致），且 `Total` / `Missing` 是数字。
- **Available 列会显示吗？** 不会单独展示，但它参与计算：需准备数量 = `Missing − Available`。
- **提示无法连接服务器？** 页面会自动降级为本地模式继续使用（档案存当前浏览器）；要启用跨设备同步，请用 `node server.js` 启动后访问，或按「部署方式三」配置云后端。
- **换个浏览器，勾选进度还在吗？** 服务器模式下在：进度保存在服务器档案中，任意设备打开同一地址都能看到；本地模式下仅限当前浏览器。
